# Reclaim 2.1.0 — Windows File Recovery

A local Windows desktop application with a professional workspace, file categories, search, recovery selection and large inline preview cards. Source storage is opened **read-only**. No account or uploads are needed for built-in recovery.

The 2.1.0 update replaces the separate preview pane and compact table with a full-width gallery of large file previews. Images show thumbnails; supported text, documents and archives show content snippets. Each card has its filename, size, condition and a recovery checkbox. The gallery decodes visible previews sequentially and bounds its thumbnail cache. PDF/media and other unsupported thumbnail formats show a clear format card. Double-click a card or use **Open file** for the full viewer with Preview, Details and Hex. Release builds include the .NET runtime and only application files, user instructions and required third-party notices.

## Repository and release

This folder is the repository root: upload its contents, including **.github/** and **.gitignore**, to GitHub. Source lives in **src/** and synthetic verification fixtures are generated by **tests/**. Build output, dependency caches, screenshots and temporary data are ignored.

The Windows workflow in **.github/workflows/build.yml** builds and verifies the app on pushes, pull requests and manual runs. It uploads **Reclaim-Windows-x64.zip** as a build artifact. To distribute a version, attach that ZIP from the workflow or **dist/** to a GitHub Release. No account tokens or credentials are required in the repository. The workflow has been prepared locally; a hosted run has not yet been performed.

## Open and recover

Extract the complete release ZIP and double-click **Reclaim/Reclaim.exe**. Keep **Licenses/** with the app. The default Windows x64 release includes the .NET runtime; a separate .NET installation is not required. PDF/audio/video previews still use the Microsoft Edge WebView2 Runtime. See [the user guide](docs/USER-GUIDE.md).

1. For live storage, click **Run as administrator**. Raw disk images work without elevation.
2. Select a drive, physical disk, original folder or **Disk image**. A deleted folder path can be typed. Physical disks appear below drive letters and scan all recognized partitions.
3. Choose **Deep scan** for directory records plus signatures, or **Quick scan** for directory records and the Recycle Bin.
4. Filter by category or search by filename/path. Preview images and text directly on the large file cards. Double-click a card for the full viewer with **Preview**, **Details** or **Hex**. Arrow keys move between cards; Space checks a card and Enter opens it.
5. Check the required cards, then use **Recover selected**. Choose another drive. Output on the source volume is blocked; for physical disks, output on any partition of that disk is blocked.
6. **Open saved folder** shows files grouped by category, with unique suffixes preventing collisions. A JSON report records completed saved/failed attempts and their evidence.

Run the app from another drive if possible. Avoid further writes to the storage that lost files. Folder junctions, symbolic links and mounted folders are rejected as live-source output locations to prevent redirection onto source storage.

## Recovery coverage

| Method | Supported behavior |
| --- | --- |
| NTFS records | Any extension, including custom extensions and extensionless files, when deleted records and data extents survive. Original filenames and surviving parent paths; resident, fragmented, sparse and multi-record unnamed streams. |
| FAT12 / FAT16 / FAT32 | Deleted short/long directory entries and surviving cluster chains. Erased short-name first characters appear as an underscore. If deletion cleared the FAT chain, a contiguous layout is inferred and marked **Needs review**; fragmented reconstruction is not guaranteed. |
| exFAT | Deleted entry-set checksums, Unicode filenames, allocation bitmap, contiguous streams and surviving fragmented FAT chains. Missing fragmented chains are unavailable rather than invented. |
| Recycle Bin | Individual files still present in the source drive's Recycle Bin, copied without removing originals. |
| Deep signatures | JPG, PNG, GIF, BMP, PDF, ZIP, DOCX, XLSX, PPTX, EPUB, 7Z, WAV, AVI, WEBP and common MP4 / MOV / M4A / HEIC / AVIF / 3GP containers. Requires supported structures and contiguous bytes. |
| Raw images / physical disks | All recognized MBR primary/logical and GPT partitions. GPT headers/tables are checksum-validated; 512- and 4096-byte GPT sectors are supported. Unrecognized bytes can be searched by signatures. |

NTFS/FAT/exFAT allocation information limits built-in deep scanning to free clusters when readable. Otherwise it searches the bounded partition's bytes; existing files and embedded content may appear. Folder filters apply to named metadata and Recycle Bin results. **Signature results cannot be restricted to an original folder**, since that information is absent.

Windows-exposed HDDs, SSDs, USB drives and SD cards can be selected. Locked phone/MTP storage and cloud/network sources do not expose the raw storage required here. Unlock BitLocker volumes in Windows and select their drive letters; encrypted physical-disk bytes cannot be decoded.

## File previews

The gallery generates image thumbnails from up to 32 MB / 25 million pixels, and text/document/archive snippets for files up to 32 MB. It loads only the visible cards, with an 80-entry cache (or enough entries for an exceptionally large viewport). These limits affect thumbnails only. The table below describes the on-demand full viewer.

| Format | Preview |
| --- | --- |
| PNG / JPG / GIF / BMP / TIFF / ICO | Decoded image fitted to the pane, first frame/page. Limits: 32 MB encoded data and 25 million pixels. |
| Text / code / CSV / JSON / XML / HTML / SVG / logs | Safe text display, including UTF-8 and UTF-16, first 256 KB. HTML and SVG are shown as text. |
| DOCX / XLSX / PPTX / ODT / ODS / ODP / EPUB | Extracted text. Office layout, images and formatting are not reproduced. Spreadsheet values may include shared-string indexes. |
| ZIP | Up to 500 archive entries. Document/archive preview limits apply independently of recovery. |
| PDF | Embedded Microsoft WebView2 PDF viewing, up to 64 MB per preview. |
| Audio / video | Embedded playback controls for codecs supported by the installed WebView2 runtime. Unsupported codecs offer Details and Hex. |
| Every other format | Name, path, method, size, condition and the first 4 KB of bytes in Hex. A visual decoder for every format is not claimed. |

PDF/audio/video require the [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/). Recovered bytes are streamed locally without exporting a file. A browser profile/cache is created on the app's drive only when that location passes source-output protection. If it would be on the source drive, **Enable PDF / media preview** asks for a workspace on another drive. Its cache folder is **.reclaim-preview-cache**. Image, document-text and hex previews read in memory. The app restricts preview navigation, downloads, new windows and external resources; the installed browser may perform its own runtime maintenance.

## Optional Advanced mode: PhotoRec

The app includes an adapter for external **PhotoRec 7.2**. **PhotoRec is not bundled**, and the external integration has not been verified with the actual engine. Built-in recovery works without it.

Download and fully extract the Windows x64 release from [CGSecurity's official download page](https://www.cgsecurity.org/wiki/TestDisk_Download). Keep its DLLs beside **photorec_win.exe**. Choose **Advanced · PhotoRec**; select that executable when prompted and an output folder on another drive. Alternatively place the extracted engine in **Reclaim/Engines/PhotoRec/**.

Advanced mode saves files **during the scan**, searches all source bytes with the engine's default enabled formats, then groups saved files by category for preview. Existing files and duplicates may appear. Original folders, filenames and deletion status are unknown. Results are already saved; **Recover selected** creates another copy. Cancellation stops the launched engine and retains found files as **Needs review**. Engine diagnostics and a report remain in the job folder. The adapter uses [PhotoRec's documented scripted interface](https://www.cgsecurity.org/wiki/Scripted_run) and does not invoke filesystem repair.

## Conditions and limits

| Condition | Meaning |
| --- | --- |
| Stored in record | Content survived in NTFS metadata or the Recycle Bin. See Method. |
| Clusters free | Mapped clusters are free now. This does not prove original bytes survived. |
| Signature found | A supported structure was found; original name/folder and deletion status are unknown. |
| Needs review | Layout was inferred, clusters reused, allocation unavailable, or an advanced scan stopped. |
| Unavailable | Required mapping is missing/invalid, compressed or encrypted. Cannot be selected. |

**No software can guarantee every deleted file from every device.** Overwriting, SSD TRIM, encryption and lost metadata can make data unrecoverable. Check exported contents before relying on them. See [Microsoft's recovery guidance](https://support.microsoft.com/en-us/windows/experience/backup-recovery/windows-file-recovery).

Built-in signature candidates are limited to **2 GB**; named NTFS metadata recovery has no corresponding limit. PDF carving stops at the first EOF, so later incremental revisions may be omitted. ZIP64/split ZIP, fragmented signature reconstruction, NTFS compression/EFS decryption, alternate streams, VHD/VHDX parsing, RAID reconstruction, disk repair and forensic snapshots are not implemented. Directory/file safety limits can omit extreme or corrupt structures. Scan notes report detected limits.

Mounted storage can change while running. Image size/timestamps, boot hashes and live deleted records are checked; these checks do not freeze free clusters or guarantee historical contents. Cancellation keeps discovered results and finished exports, removing an unfinished export. Recovery never empties the Recycle Bin.

## Demonstration and verification

Tests generate **artifacts/tests/sample-ntfs.img**, a synthetic 4 MB image with resident, fragmented, sparse and reused records plus orphan PDF/DOCX signatures, and **sample-exfat.img** for exFAT directory recovery. Samples contain no personal data and are not included in the runtime release.

Verification covers **25 core recovery/integrity checks, 15 gallery workflow checks, 5 virtual-gallery checks and embedded PDF/audio browser checks**. Tests compare recovered bytes, validate FAT/exFAT records, scan multiple MBR/GPT partitions, reject corrupted GPT checksums and changed images, and verify inline image/text previews, a 500-file virtual gallery, scrolling, file identity and cache reset. Live-drive recovery was **not tested on the user's physical storage**. The PhotoRec adapter is unverified with its actual executable.

Twelve clipping/alignment checks simulate text/geometry at 100%, 125%, 150% and 200% display densities, including large counts, button captions, matching row edges, summary-card widths, workspace edges, footer centers and unclipped source instructions. Simulations do not change Windows display settings. Alignment is also checked in an actual maximized Windows test host.

Twelve button checks exercise real, invisible Windows test hosts: 20 renders across normal/hover/pressed/disabled/focus states, transparent-parent corners, mouse/keyboard/accessibility activation, dialog results and active preview tabs. A maximized window is also captured through Windows to check the final rendering.

## Build

Requires Windows x64, the .NET 10 SDK and PowerShell. Internet access to NuGet is needed on the first build. The SDK and runtime packages restore automatically into ignored **.build/packages/**; no dependency binaries are committed.

    powershell -ExecutionPolicy Bypass -File .\build.ps1

This runs the core/UI/layout checks and publishes a self-contained Windows x64 app to **dist/Reclaim/** plus **dist/Reclaim-Windows-x64.zip**. The script replaces only its own previous **dist/Reclaim/** output. Use **-FrameworkDependent** for a smaller release that instead requires .NET 10 Desktop Runtime on the destination computer.

Native-window and embedded PDF/audio tests are opt-in because they create temporary invisible Windows test hosts. Run all checks with:

    powershell -ExecutionPolicy Bypass -File .\build.ps1 -VerifyUiWindows

Or, after building, run individual checks:

    dotnet .build/verification/Reclaim.UiTests.dll artifacts/tests/sample-ntfs.img --browser

The button rendering/interaction checks also use a temporary invisible test host:

    dotnet .build/verification/Reclaim.UiTests.dll --buttons
